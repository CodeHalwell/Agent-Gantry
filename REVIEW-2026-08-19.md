## TL;DR

1. **The 30 open PRs are really 5 distinct changes**, filed daily by scheduled Jules bot
   personas (⚡ Bolt / 🛡️ Sentinel / 🎨 Palette) because nothing ever merges. Each cluster's
   PRs append to the same `.jules/*.md` file, so they mutually conflict — merging one
   invalidates the rest of its cluster. **Merge #340 + #366 (+ #355 or #363), close the
   other 26, decide #365.** Verified locally: #340 + #366 applied together on `main` pass
   the full suite **935 passed / 76 skipped / 0 failed** with the `lancedb` extra installed
   (stronger coverage than CI, which skips LanceDB tests).
2. **Two high-severity integration bug clusters** in exactly the areas you asked about:
   OpenAI **strict-mode transcoding emits schemas the API rejects** (and `strict=True` is
   silently swallowed on every convenience path), and **execution is namespace-blind** while
   selection is namespace-aware — with two MCP servers exposing a same-named tool, the
   selected `other.search` can silently execute `default.search`.
3. **Top optimizations** (beyond the bot PRs): persistent stores re-deserialize the same
   `ToolDefinition`s on every retrieval; lazy embedder/reranker model loads block the event
   loop; LanceDB skills/list paths miss the `.select()` projection the tools path already
   has; the flagship token-savings accounting (`TokenUsageEvent`) is fully plumbed but never
   wired to any live path.
4. **Process fix**: the Jules schedules need a "check for an existing open PR first" rule
   (or a lower cadence), and the `qodana` check fails uniformly on recent PRs — likely
   failing on `main` — so it gates nothing meaningfully. Stale version labels linger
   (`DocsLayout.astro` says "v0.8.0 docs", `CLAUDE.md` says 0.9.0; `pyproject.toml` is 0.10.0).

## 2. Core hot-path optimizations (retrieve / execute / sync)

Ranked by real-world impact at typical scale (tens–hundreds of tools, one retrieval per LLM
turn). Baseline config: InMemory store + sentence-transformers embedder + console telemetry
+ rate limiter on; the router over-fetches `limit * 4` candidates (`core/router.py:285`).

| # | Impact | Finding | Where | Fix sketch |
|---|--------|---------|-------|------------|
| P1 | **Med-High** | Every persistent store re-runs `ToolDefinition.model_validate_json` per row **per retrieval** — a `limit=5` LanceDB query can validate ~20 unchanged tools every turn (1–5 ms) | `lancedb.py:462`, `remote.py:303/694/1095`, `lancedb.py:550` | Module-level content-keyed LRU: `@lru_cache` on `tool_json → ToolDefinition` (self-invalidates on change; `model_copy()` if mutation-safety matters) |
| P2 | **Med** | Lazy model construction runs **synchronously inside async coroutines** — first embed/rerank stalls the whole event loop for seconds (or minutes on first download) | `embedders/nomic.py:133-137`, `sentence_transformers.py:72`, `rerankers/cross_encoder.py:66` | `await asyncio.to_thread(self._ensure_initialized)` guarded by an `asyncio.Lock` |

## 3. Bare LLM clients & tool-spec transcoding

The two adapter hierarchies: retrieval wrappers in `integrations/llm_adapters.py` (re-exported
via `agent_gantry/openai.py` etc.) and transcoders in `adapters/tool_spec/providers.py`
(dispatched via `ToolDefinition.to_dialect`). Findings verified empirically in the venv.

### High

- **H1 — OpenAI strict mode emits schemas the API rejects.** `strict=True` only sets the
  flag (`providers.py:68-69`, Responses `:203-204`); no `additionalProperties: false`, no
  required-list transformation. Any tool with an optional parameter — including Gantry's own
  introspected tools (`introspection.py:77-79`) — 400s. Ironically the **Anthropic** adapter
  does this correctly (`providers.py:326-330`) with a docstring explaining why. Tests
  enshrine the broken output (`test_tool_spec_adapters.py:98-103`).
- **H2 — `strict` (and every per-dialect option) is unreachable and silently swallowed on
  all convenience paths.** `retrieve_tools(**kwargs)` feeds `ToolQuery`, whose default
  `extra="ignore"` drops unknown kwargs (`gantry.py:983-987`); `to_dialect` is then called
  with no options (`semantic_tools.py:168`, `llm_adapters.py:39-54`). Only manual per-tool
  `tool.to_dialect("openai", strict=True)` works.
- **H3 — Gemini/Vertex transcoding is a raw passthrough.** No unsupported-keyword stripping
  (`providers.py:440-444`): `additionalProperties`, `default`, `$ref`/`oneOf` flow straight
  into `FunctionDeclaration`, which rejects them — a registered `**kwargs` tool
  (`introspection.py:86-88`) breaks the Gemini path outright. There's no `vertexai` dialect
  (the shim reuses `"gemini"`, `llm_adapters.py:98-106`) despite the Vertex proto SDK being
  stricter.
- **H4 — The Anthropic convenience clients regress into the documented 0.5 silent-drop
  threshold trap.** `AnthropicClient.create_message` and `SkillsClient.create_message` build
  `ToolQuery` without `score_threshold` (`anthropic_features.py:156-161`,
  `anthropic_skills.py:268-273`), inheriting the 0.5 default that `schema/query.py:54-65`
  itself calls "a silent-drop trap … the convenience layers set it to 0.0 for exactly this
  reason". Every other layer complies. **One-line fix each.**

### Medium

- **M1** — Emitted schemas **alias the registry's canonical `parameters_schema`** (OpenAI
  `providers.py:65`, Anthropic `:332`, Gemini `:443`): consumer mutation corrupts the
  registry (verified). Anthropic strict shallow-copies only the top level.
- **M2** — A configured **reranker is silently never used**: `retrieve()` auto-enables only
  `if query.enable_reranking is None` (`gantry.py:912-914`) but the field is `bool = False`
  — dead branch. Make the field `bool | None = None`.
- **M3** — The round-trip layer (`from_provider_payload` / `to_tool_call` /
  `format_tool_result`) is fully built and **completely orphaned** — no wrapper or example
  uses it; examples hand-roll `json.loads` + `execute`. Anthropic's `execute_tool_calls`
  is implemented twice with divergent concurrency (sequential `anthropic_features.py:232-259`
  vs gathered `anthropic_skills.py:312-331`).
- **M4** — Malformed tool-call arguments silently become `{}` (`providers.py:96-99`,
  `:227-231`) — the same file logs a warning for the identical case in the AF adapter
  (`:601-611`).
- **M5** — **No streaming support anywhere** (no `delta.tool_calls` accumulation, no
  `input_json_delta`) — the production-normal path gets zero help.
- **M6** — Systematic class-name collisions: `OpenAIAdapter`/`AnthropicAdapter`/… exist in
  both hierarchies with unrelated contracts; easy to import the wrong one.
- **M7** — **Token-savings accounting is plumbed and never connected**: `TokenUsageEvent`
  is constructed nowhere; `record_token_usage` never called by library code; nothing reads
  `response.usage`. The flagship "~90% token reduction" is never measured automatically.
  Also `ProviderUsage.from_usage` ignores Anthropic cache tokens (`token_usage.py:58-96`).
- **M8** — No `cache_control` support, and per-turn top-k tool churn silently invalidates
  provider prompt caches every request — deserves at least a documented mitigation (stable
  ordering, tool-set reuse on cache hit).

### Low

`with_semantic_tools` swallows unknown-dialect errors into a NullHandler void
(`semantic_tools.py:263-265`); `auto_sync` is a dead parameter (`:137`); OpenAI
`format_tool_result` includes a non-spec `name` and can omit the required `tool_call_id`
(`providers.py:130-139`); provider call ids are stuffed into `ToolCall.trace_id`
(`providers.py:119`); docstring-only deprecations; `_extract_prompt` misses Responses-API
`input_text` parts (`semantic_tools.py:211`) and the Anthropic clients only extract
plain-string content (`anthropic_features.py:144-151`).

**Already good:** Responses API is a first-class dialect; Anthropic details are careful
(`is_error` results, empty-tools omission to skip the ~346-token system prompt, structured
outputs, thinking plumbing); Gemini `functionResponse.id` handling is correct and sourced;
payloads stay lean (no `extended_description`/`examples` leakage); the Mistral PyPI
quarantine is handled coherently end-to-end; `**kwargs`/`*args` correctly excluded from
introspected schemas.

## 4. Agent-framework integrations

15 adapters + the Microsoft AF stack, all funneling through a genuinely shared
`GantryToolset`/`ToolSpec` core. Verified: importing `agent_gantry` + all 15 modules loads
**zero** third-party packages, and **nothing bypasses the gantry executor** (policies, rate
limits, telemetry stay in the loop everywhere).

### High

- **F1 — Execution is namespace-blind while selection is namespace-aware.**
  `ToolSpec.ainvoke` executes `ToolCall(tool_name=self.name)` with the bare name
  (`frameworks/base.py:125`; AF bridge `agent_framework_bridge.py:364`), and the executor
  resolves via `get_tool_by_name` → prefers `default.<name>`, else first index match
  (`registry.py:145-154`). MCP tools are registered under per-server namespaces
  (`mcp_client.py:304`), so two servers exposing `search` is a supported config in which the
  selected `other.search` **silently executes `default.search`**. Live caches keyed by bare
  name have the same collapse (`pydantic_ai_live.py:257`, `autogen_live.py:154`). Fix: let
  `ToolCall` carry a namespace (or accept qualified names in the executor) and key caches by
  qualified name.

### Medium

- **F2** — OpenAI Agents export **erases optionality**: `_strict_schema` only sets top-level
  `additionalProperties: false` (`openai_agents.py:31-65`); the SDK's strict default then
  forces `required = all properties` (no null unions) — optional params become mandatory,
  nested `additionalProperties: true` raises, older SDKs 400. Null-union optionals or pass
  `strict_json_schema=False`.
- **F3** — Signature-derived frameworks lose schema fidelity: `python_signature` maps only
  top-level `type` (`base.py:176-255`) — enum/format/nested/array-items/defaults dropped for
  SK, ADK, AutoGen-static, old pydantic-ai. **CrewAI silently degrades to a no-arg tool** on
  any args-schema failure (`crewai.py:83-84`, bare except, no log).
- **F4** — The shared sync bridge is a **process-wide 1-thread pool**
  (`base.py:258-286`): one slow sync tool blocks all concurrent sync tool calls (multi-agent
  CrewAI), and a handler that itself calls `ToolSpec.invoke` **deadlocks**. Also an
  unsynchronized lazy-init race. (The bridge logic is otherwise correct — no `asyncio.run`
  misuse anywhere.)
- **F5** — LangGraph live agents freeze the executable tool superset at construction
  (`langgraph_live.py:189-198`): tools registered later (late MCP/A2A discovery) are
  selectable but not executable, failing mid-run with no warning.
- **F6** — `latest_activity` doesn't actually understand LangChain messages: `_msg_role`
  reads `.role` (`query/strategies.py:121-127`) but LangChain exposes `.type` — every
  message yields role `""`, so AI messages can drive retrieval and the tool-result cap/skip
  logic never applies. The `langgraph_live.py:119-133` docstring claims the opposite; tests
  only cover HumanMessage-tailed states.
- **F7** — "per-turn" `live_tier` conflates automatic query derivation (ADK, Strands,
  pydantic-ai, LlamaIndex, LangGraph, OpenAI-Agents) with **app-driven** (AutoGen's
  `Workbench.set_query`, SK's manual `provider.refresh(history)`) — stale-query traps for
  the latter two deserve an explicit sub-flag or README column.

### Low

`auto_sync` dead in `SemanticToolSelector` too (`semantic_tools.py:137`); `refresh.py:101-166`
is a drifted copy of `query/strategies.py` helpers (missing AF `contents` walking);
`_json_type_to_python` duplicated (`base.py:251` vs `agent_framework_bridge.py:517`);
`DEFAULT_TOOL_LIMIT = 5` exists to stop drift yet `llm_adapters.py:35` and `refresh.py:220`
still default to 3; dict tool results reach models as Python repr via `str()` in
OpenAI-Agents/AutoGen (`openai_agents.py:56-58`, `autogen_live.py:247-251`) while the AF
bridge properly `json.dumps`; `GantryToolset.select` doesn't clamp `limit` to `ToolQuery`'s
`le=50`; `tools_already_used` (anti-repetition) is never passed by any of the eight per-turn
providers; reverse importers exist only for LangChain/CrewAI/LlamaIndex; no streaming
passthrough (`run_streamed` etc.); the `"relative:<frac>"` threshold mode exists only in the
AF bridge, not the 14 native adapters.

**Already good:** verified lazy-import hygiene; universal execute-through-gantry; shared
selection core with `required`/`always_include` pinning and fail-fast semantics; a
parameterized conformance suite across all adapters (~5,000 lines of framework tests);
exceptional error-handling documentation that matches the code; careful async correctness
(per-event-loop locks, ContextVars in the AF provider, CrewAI `asyncio.run`-trap handling).
