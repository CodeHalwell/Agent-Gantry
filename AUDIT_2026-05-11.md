### 3.2 Anthropic — one refactor required (applied)

**Finding P3-1 — APPLIED**: `AnthropicClient.create_message()` placed the `effort` level for adaptive
thinking inside the `thinking` block as `{"type": "adaptive", "effort": "medium"}`. Per the current
Anthropic adaptive thinking API documentation, `effort` is a separate top-level parameter passed as
`output_config={"effort": "medium"}`. The `thinking` block for adaptive mode should only contain
`{"type": "adaptive"}` plus an optional `"display"` field.

**Why this matters**: The Anthropic SDK at 0.100.0 may reject `effort` as an unrecognised field inside
the thinking config, returning a 400 error, or silently discard it — in either case, the intended effort
level was never applied.

**Source**: https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking (Python examples)

#### Unified diff — `agent_gantry/integrations/anthropic_features.py`

```diff
-        # Build thinking payload — adaptive takes precedence over extended when both are set.
-        # Display key and kwargs assignment happen once after the block is constructed.
+        # Build thinking payload — adaptive takes precedence over extended when both are set.
+        # Per the Anthropic API docs (https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking),
+        # the 'effort' parameter belongs in output_config, not in the thinking block.
         if "thinking" not in kwargs:
             thinking_block: dict[str, Any] | None = None
             if self._features.adaptive_thinking_effort:
-                thinking_block = {
-                    "type": "adaptive",
-                    "effort": self._features.adaptive_thinking_effort,
-                }
+                thinking_block = {"type": "adaptive"}
+                # effort is a top-level output_config field, not a thinking block field.
+                if "output_config" not in kwargs:
+                    kwargs["output_config"] = {"effort": self._features.adaptive_thinking_effort}
             elif self._features.enable_extended_thinking and self._features.thinking_budget_tokens:
```

**Risk level**: Safe internal. The public `AnthropicFeatures` / `AnthropicClient` API is unchanged;
the fix corrects the wire format sent to the Anthropic endpoint.

**Additional documentation changes in the same file:**

- Module docstring: updated to describe `output_config.effort` pattern and note extended thinking
  deprecation on Opus 4.6 / Sonnet 4.6 and rejection on Opus 4.7.
- `AnthropicFeatures.enable_extended_thinking` comment: updated to say "Rejected on claude-opus-4-7
  (use adaptive thinking instead). Deprecated but functional on claude-opus-4-6 and claude-sonnet-4-6."
- `AnthropicFeatures.adaptive_thinking_effort` comment: updated to say "The effort value is sent as
  `output_config.effort` (NOT inside the thinking block)."
- `AnthropicClient` class docstring: updated to show correct API shapes.
- `create_anthropic_client()` Args section: updated `enable_thinking` and `adaptive_effort` to reflect
  the correct wire format and deprecation status.

**Source**: https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking

## 7. Test and Migration Plan

### New / Updated Tests Required

#### Required (for applied bug fix)

1. **`tests/test_anthropic_features.py`** — add or update the test that exercises
   `AnthropicClient.create_message()` with `adaptive_thinking_effort` set:
   - Assert that `kwargs["output_config"] == {"effort": "medium"}` (or the set value).
   - Assert that `kwargs["thinking"] == {"type": "adaptive"}` (no `effort` key inside).
   - Assert that `kwargs["thinking"]` is absent when neither adaptive nor extended thinking is configured.

   Example skeleton:
   ```python
   async def test_adaptive_thinking_effort_in_output_config():
       """effort must be in output_config, not inside the thinking block."""
       client = AnthropicClient.__new__(AnthropicClient)
       client._features = AnthropicFeatures(adaptive_thinking_effort="high")
       client._client = AsyncMock()
       client._gantry = None

       captured_kwargs: dict = {}

       async def fake_create(**kwargs):
           captured_kwargs.update(kwargs)
           return MagicMock(content=[])

       client._client.messages.create = fake_create

       await client.create_message(
           model="claude-opus-4-7",
           messages=[{"role": "user", "content": "hello"}],
           max_tokens=128,
           auto_retrieve_tools=False,
       )

       assert captured_kwargs.get("thinking") == {"type": "adaptive"}
       assert captured_kwargs.get("output_config") == {"effort": "high"}
       assert "effort" not in captured_kwargs["thinking"]
   ```

2. **`tests/test_anthropic_features.py`** — add a test that verifies `display` is still placed
   correctly inside the `thinking` block when `thinking_display` is set:
   ```python
   async def test_adaptive_thinking_display_in_thinking_block():
       """display belongs inside thinking block, not in output_config."""
       # ... (similar setup)

           adaptive_thinking_effort="medium",
           thinking_display="summarized",
       )
       # ...
       assert captured_kwargs["thinking"] == {"type": "adaptive", "display": "summarized"}
   ```

   ```python
       assert captured_kwargs["output_config"] == {"effort": "low"}
   ```
