### 3.1 OpenAI

**Status: No action required.**

**Source**: https://platform.openai.com/docs/api-reference/responses (accessed 2026-05-01)

### 3.2 Anthropic

**Status: No action required.**

All call sites use `client.messages.create(...)` (Messages API) with the `tools` field and
`tool_use` / `tool_result` content blocks. Tool result round-tripping correctly uses
`tool_use_id`. Thinking modes are correctly configured:

- `adaptive`: `thinking={"type": "adaptive", "effort": "medium"}` — correct for Opus 4.6+,
  Sonnet 4.6+, Opus 4.7.
- `extended`: `thinking={"type": "enabled", "budget_tokens": N}` — no beta header required.
- `interleaved`: `anthropic-beta: interleaved-thinking-2025-05-14` — documented as silently
  ignored on Opus 4.6+/Sonnet 4.6+/Opus 4.7; relevant only for older models.

**Note (good next step)**: `AnthropicAdapter.format_tool_result()` returns a content block
(`{"type": "tool_result", "tool_use_id": ..., "content": ...}`) without a `role`. Callers
must wrap this in a user message:
```python
messages.append({"role": "user", "content": [adapter.format_tool_result(...)]})
```
This is structurally correct but asymmetric with `OpenAIAdapter.format_tool_result()` which
returns a complete message dict (including `role: "tool"`). The docstring should be updated to
make the wrapping requirement explicit. **Needs confirmation** if AF-bridged callers need
adjustment.

**Source**: https://platform.claude.com/docs/en/api/messages (accessed 2026-05-01)

### 3.3 Google Gemini

`GeminiAdapter.format_tool_result()` correctly places the `id` field inside

**Source**: https://ai.google.dev/gemini-api/docs/function-calling (accessed 2026-05-01)

## 4. Framework Integration Refactors

### 4.1 Microsoft Agent Framework (Priority)

#### 4.1.1 `agent-framework` 1.2.2 — Breaking Change (Applied)

**Release date**: 2026-04-29 (same day as previous audit; not captured then).  
**Source**: https://github.com/microsoft/agent-framework/releases?q=tag%3Apython-1&expanded=true

The key breaking change in 1.2.2:

> *Orchestration terminal outputs standardised as `AgentResponse`, affecting
> `Workflow.as_agent()` return values.*

`WorkflowAgent.run()` (which delegates to `Workflow.as_agent().run()`) now returns an
`AgentResponse` object. The text content is accessed via `.value`. For backward compatibility
with earlier 1.x releases that returned an object with `.text`, the examples and any consumer
code should use the accessor chain:

```python
output = getattr(response, "value", None) or getattr(response, "text", None) or str(response)
```

**Files updated**:

##### `examples/agent_frameworks/agent_framework_example.py`

```diff
-    response = await workflow_agent.run(user_query)
-    print(f"Response: {response}")
-    return str(response)
+    response = await workflow_agent.run(user_query)
+    # AF 1.2.2: WorkflowAgent.run() (Workflow.as_agent()) returns AgentResponse.
+    # Access .value for the text output; fall back to .text or str() for
+    # compatibility with earlier AF 1.x releases.
+    output = getattr(response, "value", None) or getattr(response, "text", None) or str(response)
+    print(f"Response: {output}")
+    return output
```

**Risk**: Safe with shim (backward compatible accessor chain).

##### `examples/agent_frameworks/agent_framework_orchestration_example.py`

Three call sites updated (sequential, concurrent, handoff) with the same `getattr` accessor
chain:

```diff
-    result = await workflow.run(query)
-    print(f"[sequential] result:\n{result}")
+    result = await workflow.run(query)
+    output = getattr(result, "value", None) or getattr(result, "text", None) or str(result)
+    print(f"[sequential] result:\n{output}")
```

(Same pattern for concurrent and handoff `workflow.run()` calls.)

**Risk**: Safe with shim.

## 5. Universal Tool-Calling Design

### 5.1 Contract Verification

The existing `ToolSpecAdapter` protocol and `ToolCallPayload` model are verified as sound.
No structural changes required.

**`ToolSpec` contract** (canonical internal representation — `ToolDefinition`):

| Field | Type | Description |
|-------|------|-------------|
| `name` | `str` | `^[a-z][a-z0-9_]*$`, ≤128 chars |
| `description` | `str` | 10–2000 chars |
| `parameters_schema` | `dict` | JSON Schema (OpenAI-style `object`) |
| `capabilities` | `list[ToolCapability]` | Permission classification |
| `version`, `namespace` | `str` | Provenance and routing |

### 5.2 Per-Provider Translator Status

| Adapter | `to_provider_schema` | `from_provider_payload` | `format_tool_result` | Status |
|---------|---------------------|------------------------|----------------------|--------|
| `OpenAIAdapter` | `{type: function, function: {name, desc, params}}` | Parses `{id, type, function: {name, arguments}}` | Full message with `role: "tool"` | ✅ Correct |
| `OpenAIResponsesAdapter` | `{type: function, name, desc, params}` (flat) | Parses `{type: function_call, call_id, name, arguments}` | `{type: function_call_output, call_id, output}` | ✅ Correct |
| `AnthropicAdapter` | `{name, description, input_schema}` | Parses `{type: tool_use, id, name, input}` | Content block `{type: tool_result, tool_use_id, content}` — **caller must wrap in user message** | ✅ Correct; docstring note needed |

| `GroqAdapter` | Inherits `OpenAIAdapter` | Inherits `OpenAIAdapter` | Inherits `OpenAIAdapter` | ✅ Correct |
| `AgentFrameworkAdapter` | OpenAI-style + optional metadata | Handles both OpenAI-style and simplified AF `{name, arguments}` format | Inherits `OpenAIAdapter` | ✅ Correct |

### 5.4 Tool Name Normalisation

`ToolDefinition.name` is enforced as `^[a-z][a-z0-9_]*$` at schema level. All providers
accept underscored lowercase identifiers. No normalisation shim needed.

### 5.5 Enum / Value Coercion

`GeminiAdapter.to_provider_schema()` passes `parameters_schema` through verbatim. Gemini
accepts a JSON Schema subset including `enum` fields in `properties`. No coercion needed.

### 7.3 Changelog-Ready Migration Notes

#### mistralai 2.x (Breaking for consumers of `LLMClient` internals)

```markdown
### Changed
- **`mistralai` upgraded to `>=2.0.0`** (was `>=1.0.0,<2.0.0`):
  `LLMClient` for the Mistral provider no longer holds a long-lived `self._client`
  instance. Instead it stores `self._mistral_api_key` and builds a fresh
  `async with Mistral(...)` context manager on each `classify_intent()` call.
  This matches mistralai 2.x's required resource model.
  *Impact*: callers that accessed `llm_client._client` directly for Mistral will
  find `None`; use `llm_client._mistral_api_key` to confirm initialisation, or
  call `await llm_client.health_check()`.
  *Risk*: Safe internal — no change in observable `classify_intent()` behaviour.
```

#### `agent-framework` 1.2.2 `AgentResponse` (Breaking for orchestration result consumers)

```markdown
### Changed
- **`agent-framework` bumped to `>=1.2.2,<2.0.0`**:
  `WorkflowAgent.run()` and orchestration builder `.run()` calls (Sequential,
  Concurrent, Handoff) now return `AgentResponse` objects in AF 1.2.2.
  Access the text output via `response.value` (AF 1.2.2+) or `response.text`
  (AF 1.x pre-1.2.2). The bridge examples use a backward-compatible accessor:
  `getattr(response, "value", None) or getattr(response, "text", None) or str(response)`.
  Code that passes `str(response)` directly to downstream consumers should be
  updated to use this pattern or explicitly access `response.value`.
  *Risk*: Safe with shim — backward-compatible accessor pattern applied throughout.
```
