🚨 Severity: HIGH
💡 Vulnerability: The `ToolDefinition.name`, `version`, and `namespace` fields lacked sufficient validation against newline injection. The Rust regex engine's `$` anchor in Pydantic's `pattern` matches the end of the line (not just the end of the string), allowing attackers to bypass validation by appending a newline (e.g., `"valid_name\n"`). This could lead to log injection or HTTP header injection vulnerabilities.
🎯 Impact: Attackers could inject malicious newlines, bypassing expected structural constraints, leading to log spoofing or potentially HTTP response splitting in downstream systems that consume the model fields.
🔧 Fix: Added a `@field_validator` checking for `\n` and `\r` explicitly across the entire string (using `isinstance(v, str)`) rather than relying on the regex `$` anchor.
✅ Verification: Ran `pytest` suite ensuring all validations pass correctly and verified the new error handling correctly blocks multiline input strings.
